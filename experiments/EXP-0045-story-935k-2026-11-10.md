# EXP-0045: Story 935K, corrected split and release package

This is the completed 100M-token run described in the publication request, not a new training experiment. It follows the exploratory CPU pilot in [PR #1](https://github.com/thekester/slm-tavenel/pull/1), whose 27M-token weights and initial split are not this model. The initial pilot could put stories from one synthetic completion in both train and dev; the run here uses the completion-group-disjoint v2 subset and a fresh initialization.

## What was actually run

- Native architecture: `configs/model/slm-story-935k.yaml`, 935,040 unique parameters, four layers, width 128, 1,024-token byte-level BPE, shared embedding/output table, no attention gate or QK norm.
- Training: one seed (421201), 6,104 AdamW updates of 16,384 token positions, totaling 100,007,936 positions. Training windows were 256 tokens despite the configured maximum positional length of 1,024.
- Data: first pinned SimpleStories shard, 60,000 train and 3,185 local dev stories. Tokenizer learned from a seeded sample of 30,000 train documents. Raw shard, corpus, tokenizer and token-shard hashes are in the [model record](../docs/model-cards/slm-tavenel-story-935k/training_record/).
- RTX 4060 Laptop GPU, roughly 9.4 minutes, 7.344 Wh GPU board energy, peak allocated VRAM 0.566 GB. CPU/whole-system energy and carbon emissions were not measured.
- Native checkpoint: `runs/EXP-0045/story-935k-100m-v2-s421201/checkpoints/step_00006104.pt`, SHA-256 `0f9646fe473bab436d6d2200c3bc1d6668fe17ae70698cf7118b03a6dbd93e87`.
- Existing standard Llama export: `data/models/fluency/story-935k-100m-v2`, bfloat16 safetensors SHA-256 `8804d57668ac492454d9835841ff2a57f7867dbcbb36df4452ffedfa8813c9a8`.

The original run records main commit `34a92771b3d9a95356d81a9296c6bec0844b6904` with `dirty: true`. Model configs and fluency tooling originate from PR #1 at `14bb331503df1537f6efb1f8d00a907a06b5269e`; the corrected split builder and 100M-token config were in a local overlay. These source files are now committed for reconstruction. This does not retrospectively turn the run into an execution from a clean commit. The original manifests retain their fields and hashes.

The evidence directory has a scoped `-text` Git attribute so the archived bytes retain their hashes across platforms. The source-code hash record captures local execution bytes; source files elsewhere in the repository still follow Git's normal line-ending conversion, which can change their byte hashes without changing Python semantics.

## Results and scope

| Model / condition | Bits per byte | Notes |
|---|---:|---|
| Story 935K, native float32, 256-token chunks | 0.937006 | Correct training-length comparison |
| Story 935K, exported bfloat16 weights loaded as CPU float32, 256-token chunks | 0.937012 | Exact released artifact; verified separately |
| tiny1m, published snapshot, native 256-token context | 1.670289 | Same 3,185 SimpleStories dev texts, different training source/tokenizer/budget |
| Story 935K, native float32, 512-token chunks | 1.145320 | Context diagnostic |
| Story 935K, native float32, 1,024-token chunks | 1.291448 | Context diagnostic |

Final sampled validation cross-entropy during training was 1.9662 nats per token. This is not a sealed-test result. Dev BPB is deliberately kept separate from that sampled validation metric.

The favorable likelihood gap is domain-specific: dev comes from Story 935K's own source. It does not demonstrate that the model tells more coherent stories, wins on general accuracy, or outperforms TinyStories under a neutral or budget-controlled protocol. One seed, one shard, no uncertainty intervals, and no blind human scores. The 30 raw comparative generations are archived; their repetition rates are diagnostics rather than a quality ranking. The fixed examples include object loss, character changes and unfinished text.

The export tensor mapping is exact after the documented bfloat16 rounding. On two fixed prompts, rounded-native/export logits differ by at most `2.10e-5`; the original full-precision checkpoint differs by up to `0.102` because of rounding. Cached and uncached greedy tokens match on these probes. Thirteen targeted export/fluency tests pass. These are packaging and sampling checks, not a scientific validation of story quality.

## Reproduce locally

The source stays `candidate`. The commands below reconstruct the exploratory research run; they do not grant public redistribution permission. Use a new output directory if preserving an existing reconstruction. From the project root in PowerShell:

```powershell
pip install -e ".[hf,data-curation,energy,dev]" sentencepiece
$env:PYTHONPATH = 'src'
@'
from huggingface_hub import hf_hub_download
hf_hub_download('SimpleStories/SimpleStories', 'data/train-00000-of-00007.parquet',
    repo_type='dataset', revision='e63b8adc3b1a1bdc7cac5b500d150b71346b0628',
    local_dir='data/raw/simple-stories-e63b8adc')
'@ | python -
python scripts/build_exp0045_simple_stories_v2.py --parquet data/raw/simple-stories-e63b8adc/data/train-00000-of-00007.parquet --out data/processed/exp0045-simple-stories-v2
python -m slm tokenizer train --inputs data/processed/exp0045-simple-stories-v2/train.jsonl --out data/processed/exp0045-tokenizer-v2-s421201 --vocab-size 1024 --max-docs 30000 --seed 421201
@'
from slm.data.shards import encode_fixed_splits
encode_fixed_splits('data/processed/exp0045-tokenizer-v2-s421201/tokenizer.json',
    {'train': ['data/processed/exp0045-simple-stories-v2/train.jsonl'],
     'dev': ['data/processed/exp0045-simple-stories-v2/dev.jsonl']},
    'data/tokens/exp0045-simple-stories-v2')
'@ | python -
python -m slm train configs/train/exp0045-story-100m-v2.yaml
python -m slm export --checkpoint runs/EXP-0045/story-935k-100m-v2-s421201/checkpoints/step_00006104.pt --tokenizer data/processed/exp0045-tokenizer-v2-s421201/tokenizer.json --out data/models/fluency/story-935k-100m-v2
python scripts/generate_story.py "Once upon a time, a fox found a key." --seed 0
python scripts/package_story_935k.py
```

Compare reconstructed hashes with the archived manifests. Repeated runs can differ with software/hardware and BPE-library behavior; byte-identical reconstruction is not asserted without that check. The exported tokenizer is also part of the Hub package, so inference need not retrain it.

To rerun the five-prefix comparison, download `shibatch/tiny1m@fdacad8ff9dc27bd72c77d3684075a494be1ba11` locally and pass a two-snapshot JSON list to `scripts/compare_fluency.py`. The original exact list is [archived](../docs/model-cards/slm-tavenel-story-935k/training_record/generation-comparison/snapshots.json); the full decoding settings and local hashes are in the adjacent manifest. Give the blank review CSV without its key to reviewers; no ratings have been filled in.
