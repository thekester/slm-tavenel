# EXP-0044: restore useful free generation at approximately 1M parameters

Status: diagnosis and experiment preparation. **No new weights have been trained,
no superiority has been demonstrated, and no released model is replaced.**

**Scope amendment, 2026-11-10:** the user now targets English story quality with
a strict total-parameter constraint. [EXP-0045](EXP-0045-stories-strict-1m-2026-11-10.md)
supersedes the prospective bilingual mixture and 1.18M ceiling below. The
1,166,720-parameter candidate is outside the new budget; it remains here only
as an untrained historical proposal. The completed generation diagnosis and
its archived results remain valid. EXP-0045 caps candidates at 935,040 total
unique parameters, matching the actual benchmark reference.

## Why this experiment

The published SLM-Tavenel 1M checkpoint was designed for EXP-0010's paired
attention-gate experiment on a narrow scientific corpus, not fluent everyday
storytelling. Its 15,990,784 presented training tokens and near-chance QCM scores
do not establish general language ability. EXP-0011 already found that another
16M presentations of the same data worsened fixed-window development loss from
3.64577 to 3.84200. Repeating that run is not the proposed intervention.

Pinned baseline: `athenista/slm-tavenel-1m@77d1d8b09af0ff8583844460f383f8f1c4f9bd96`.
Its weights have 1,181,920 unique parameters, including 786,432 shared
embedding/output parameters (66.54%), leaving 395,488 outside that table.
The existing benchmark's reference is `shibatch/tiny1m`, **not**
`roneneldan/TinyStories-1M`. Its pinned safetensors at
`fdacad8ff9dc27bd72c77d3684075a494be1ba11` contain 935,040 unique parameters,
131,072 in its separate input/output tables and 803,968 elsewhere. Count the
actual tensors: the reference card's prose and its file metadata disagree.

## Goal and hypotheses

Preserve English/French capability and all existing provenance/instrumentation.
Test whether more suitable, diverse simple prose improves coherent continuation;
then test whether reducing the vocabulary releases useful block capacity within
the current 1.18M total-parameter ceiling. Neither hypothesis guarantees success.

Story quality in English is the direct comparison with tiny1m. French is a
separate retained-capability evaluation, not an average that can hide failure
in English. Scientific-domain BPB is a regression metric, not the release goal.
No chat-assistant, reasoning, factual-accuracy or agentic-capability claim follows.

## Stage 0: reproducible generation diagnosis (implemented)

`scripts/compare_fluency.py` reads local frozen HF snapshots. It retains exact
prompt/output token IDs, completions, stopping reasons, tokenizer/code/weight
hashes, declared Hub revisions, device, environment, seeds, sampling settings
and elapsed time. It never invokes a remote judge. Repetition metrics are
diagnostics only: fluent nonsense can have low repetition.

Compare 320 decoded UTF-8 bytes, not the same number of differently sized tokens.
Keep the final token's byte overshoot visible. Stop on EOS/context/token cap and
record truncation; do not silently extend tiny1m's 256-token context or select
the best sample. Greedy decoding is run once; sampling uses temperature 0.8,
top-p 0.9, two seeds. All 8 diagnostic prompts are published. They are now
development material, never a secret test set. Latencies use full recomputation
without cache and are not deployment-speed benchmarks. CPU energy is unmeasured.

Reproduce from the repository root (install an appropriate PyTorch build first):

```bash
pip install -e ".[hf,dev]" transformers==4.57.6 sentencepiece==0.2.1
python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download('athenista/slm-tavenel-1m',
    revision='77d1d8b09af0ff8583844460f383f8f1c4f9bd96',
    allow_patterns=['config.json', 'generation_config.json', 'hf_config.py',
                    'hf_model.py', 'model.safetensors', 'tokenizer.json',
                    'tokenizer_config.json', 'special_tokens_map.json'],
    local_dir='data/models/fluency/tavenel')
snapshot_download('shibatch/tiny1m',
    revision='fdacad8ff9dc27bd72c77d3684075a494be1ba11',
    allow_patterns=['hf/*'], local_dir='data/models/fluency/tiny1m')
PY
# Read the downloaded custom inference code before opting in to its execution.
python scripts/compare_fluency.py --snapshots configs/eval/fluency-snapshots-v1.json \
    --prompts configs/eval/fluency-dev-v1.jsonl --output runs/EXP-0044/diagnostic-v1 \
    --trust-custom-code
```

Outputs: `manifest.json`, `generations.jsonl`, `blind_review.csv`,
`review_key.json`. Give only the CSV to reviewers; keep the model key separate.
The CSV groups the same prompt/temperature/seed and shuffles model order. Scores
must remain empty until humans actually review them. It is not a statistically
powered blinded preference study.

## Stage 1: data before more compute (not run)

Build and freeze a new source-reviewed simple-prose mixture in both languages.
Start with an exploratory target of 50% English/50% French by UTF-8 training
bytes, predominantly simple narrative/everyday prose; preserve scientific prose
only as a measured minority. The exact components and proportions must be fixed
before training. This is a candidate recipe, not a claimed optimal mixture.

Use `docs/DATA_POLICY.md` and the existing source registry/pipeline: pin every
source, document component rights, preserve attribution and source IDs, redact
PII, remove recurring extraction artefacts (HAL headers, page furniture,
references/equation fragments), deduplicate and decontaminate. Measure removals;
do not infer that every HAL occurrence is bad. Split by source document and
near-duplicate group before tokenizer fitting. A longer training budget does not
justify repeatedly sampling the current narrow corpus.

TinyStories may remain an external **evaluation reference**. Do not silently add
its text to released training data or label it CC0/MIT: its synthetic provenance
and actual data/output terms require their own review. An open teacher is an
optional later experiment, with checkpoint/license, prompt, seed, sampling,
filters and generated-record lineage. Changing a registry status or removing
checks is not an optimization. Template smoke data are not a quality corpus.

Current limitation: the new prose corpus and its source review are not supplied
by this change. The training YAML points to a deliberately separate, presently
unbuilt dataset. Training and a release claim cannot proceed on that YAML alone.

## Stage 2: staged capacity and budget experiments (not run)

| Arm | Vocabulary | Width / layers / FFN | Total parameters | Purpose |
|---|---:|---|---:|---|
| Published architecture | 8,192 | 96 / 4 / 256 | 1,181,920 | Retrain on the new corpus as a data-recipe control |
| Compact vocabulary control | 2,048 | 96 / 4 / 256 | 592,096 | Observe the tokenizer/size tradeoff |
| Capacity reallocation | 2,048 | 128 / 4 / 480 | 1,166,720 | More block capacity within the original ceiling |

The two new models keep RMSNorm, QK normalization, GQA, RoPE, attention gates,
SwiGLU, weight tying, hook points and the existing training loop. They need
**new training from scratch** and their own train-only 2,048-entry tokenizer;
an 8,192-token checkpoint cannot be loaded by merely editing its config.

Pilot: 100,007,936 presented tokens (6,104 steps × 16,384 tokens), AdamW,
cosine schedule 1e-3 to 1e-4, 300 warmup steps. These are starting settings to
test, not validated hyperparameters. Seeds 421201 and 421202 must both be kept.
The released checkpoint is an external baseline; it is not a matched training
control because data, optimizer schedule and training budget differ.

Compare vocabulary-2048 block variants on identical shards/order/budget. For
8192-vs-2048, equal tokens are not equal text/context/compute: report tokenizer
fertility, raw bytes, unique source coverage, repetition, effective context,
FLOPs, GPU-hours and energy. Treat this as a recipe comparison, not proof of a
pure tokenizer effect. Also compare at matched data exposure/compute before
making an efficiency claim. Do not multiply steps by a tokenizer-dependent
"tokens per parameter" heuristic and call that sufficient language training.

Once the reviewed splits exist, train the tokenizer on **train only** with
`slm.tokenizer.train`, and encode fixed train/dev/test splits with
`slm.data.shards.encode_fixed_splits`. Freeze their hashes. The following commands
are then available; they are not a claim that the data already exist:

```bash
python -m slm train configs/train/exp0044-1m-fluency-pilot.yaml
python -m slm train configs/train/exp0044-1m-fluency-pilot.yaml --set \
    seed=421202 out_dir=runs/EXP-0044/1m-v2048-reallocated-s421202
python -m slm train configs/train/exp0044-1m-fluency-pilot.yaml --set \
    model=configs/model/slm-1m-v2048-control.yaml \
    out_dir=runs/EXP-0044/1m-v2048-control-s421201
python -m slm train configs/train/exp0044-1m-fluency-pilot.yaml --set \
    model=configs/model/slm-1m-v2048-control.yaml seed=421202 \
    out_dir=runs/EXP-0044/1m-v2048-control-s421202
```

Predeclare a development checkpoint rule: lowest equal-language macro BPB,
then earliest checkpoint on a tie; do not select on QCM/test results. Compare
BPB on identical texts, never raw perplexity across different tokenizers.
Do not scale to 300M/1B token presentations before both seeds improve dev
generation and BPB without a memorization warning. Measure time with a short
throughput run on the actual laptop rather than extrapolating the old 3.6-minute
run to a different tokenizer and architecture.

## Confirmatory adoption rule (future, not executed)

Before training, freeze a fresh held-out corpus and at least 200 new English
story prefixes plus 200 French prefixes, disjoint from development prompts and
training sources. Use two human raters blind to checkpoint identity; lock a
0–4 rubric for grammar, coherence and relevance, tie handling and disagreement
resolution. Track language switching and story endings separately. Bootstrap
at the prompt level, nesting sampling/training seeds; do not count completions
of the same prompt as independent evidence.

Adopt only if both training seeds improve held-out macro BPB over the retrained
control, French preference against the old checkpoint has a 95% lower bound
above 50%, and English preference against the pinned tiny1m reference has a
95% lower bound above 50%. Count ties as half. Predeclare the final test once;
new searches after inspecting it need a new test set. Preserve all negative
results. Stronger words such as "large improvement" need an effect size and
interval, not just a pass/fail result or one attractive generation.

## Traceability and openness

Keep run manifests, hashes, optimizer/RNG states, checkpoints, all seeds,
loss/gradient/LR logs, activation/gate/attention diagnostics, parameter update
ratios and NVML energy. Missing energy remains null, not zero. Preserve code,
tokenizer, source/selection/preprocessing information and weights under the
applicable terms. Update the OSAID self-assessment for the **new** release; do
not inherit the old assessment or describe it as OSI certification. Observed
attention/gate patterns remain observations, not causal explanations.

Research such as [Meta-Harness](https://arxiv.org/abs/2603.28052) improves the
code surrounding already capable models. That is a different intervention from
learning grammatical language in a 1M base model. No Qwen percentage transfers
automatically to this experiment.
