# EXP-0042: LFM3-VL-2B with a compiled computer as calculator (preregistered 2026-11-06, before any scored run)

Axis: `experiments/AXIS-compiled-computer-qwenputer-2026-11-05.md` (route B, separate stream).
Model: `LiquidAI/LFM3-VL-2B@71d8e745` (LFM Open License v1.0; weights unchanged), local snapshot
`data/models/lfm3-vl-2b-71d8e745`, `transformers==5.21.1` isolated in `data/envs/tf5`, bf16.
Relay: `scripts/lfm3_compiled_computer.py` (native XML tool calls; greedy decoding; no thinking).

## Smoke test (not part of the scored results)

Three hand-picked questions on CPU (2026-11-06): with the compiled machine, LFM3 called `multiply`/`add`
with the right arguments and reported the right result for 48213 x 9917 (10,152 trace tokens),
987654321987 + 123456789123 (2,673) and 734921 x 58337 (14,391). Observation used to fix the protocol:
with two tools declared and no system prompt LFM3 declined to answer; a system sentence asking it to
call the tools for integer arithmetic fixes this, so it is part of the protocol for the tool arms.

## Design

Items (generated by a seeded script before scoring, seed 20261106): integer addition with both operands
of 6, 10 and 15 digits, and multiplication of 3x3, 5x4, 6x5 and 8x8 digits; 100 items per cell
(700 items); question template "What is {a} {op} {b}?" with op in {+, *}.

| Arm | System prompt | Tools | Who computes |
|---|---|---|---|
| N, model alone | "You are a helpful assistant." | none | LFM3 |
| P, host tool | + "For any arithmetic on integers, call the provided tools instead of computing by hand." | add, multiply | Python |
| C, compiled | same as P | add, multiply | `CompiledMachine` (`ADD_PROGRAM` / `MUL_PROGRAM`) |

Scoring: the final answer is correct if the last integer in it (digits with optional thousands
separators removed) equals the exact result. Also reported: tool-call rate, argument-copy accuracy
(the call's a and b equal the question's), compiled-machine correctness on the calls it received,
trace tokens per call, wall time.

**Criteria (fixed now).** (1) The compiled machine is exact: C's tool results equal Python's on 100% of
well-formed calls (any mismatch is a bug, reported). (2) C beats N if its accuracy is higher by at least
10 points on the multiplication cells pooled, with a 95% paired bootstrap interval excluding zero.
(3) C vs P: equal accuracy is expected (both tools are exact); any difference must come from the relay
and is analysed item by item. Secondary: accuracy by cell, failure modes (no call, wrong arguments,
wrong final transcription).

## Limits fixed in advance

Single model, greedy decoding, one prompt template; the computer runs as a separate compiled stream
(Python calls of compiled modules), not inside LFM3's forward pass; only addition and multiplication;
operands up to 16 digits; the result is a derivative of LFM3 under the LFM Open License, not an
SLM-Tavenel model.
